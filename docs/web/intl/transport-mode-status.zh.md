# 传输方式栏圆点状态说明

**适用区域**：国际服务集群（例如 `api.shrimpsend.com` / `ws.shrimpsend.com`）

在 ShrimpSend 中打开某台设备的会话后，聊天区域顶部会显示 **传输方式** 栏（HTTP 局域网直连、WebRTC 局域网直连、S3 云端等）。每种传输方式名称右侧有一个 **小圆点**，表示该路线当前的连通状态。

点击传输方式栏标签旁的 **?** 图标，或在各路线按钮上悬停，可查看详细说明。

## 圆点颜色含义

| 颜色 | 含义 | 说明 |
|------|------|------|
| **绿色** | 已验证可用 | 探针确认此路线可走通，选择后发送预期能成功 |
| **蓝色** | 仅反向拉取（HTTP） | 对端能访问本机 HTTP，但本机无法直连对端；文件仍可传输，但方向可能不对称 |
| **琥珀色** | 可尝试，尚未验证（HTTP） | 直连尚未确认，你仍可手动切换到此方式尝试 |
| **主题色** | WebRTC 尚未检测 | 未做 WebRTC 专项检测（例如 LAN 已通时会跳过），不代表一定不可用 |
| **灰色** | 不可用 | 当前条件下此路线走不通（如 S3 未配置、WebRTC 探针失败等） |

## 仅反向拉取是什么

部分网络环境（NAT、防火墙、路由层级不同）会出现 **单向可达**：例如手机能访问电脑，但电脑无法主动连到手机。此时 HTTP 路线可能显示 **蓝色** 圆点，表示只能通过 **反向拉取** 完成传输——由能访问本机的一方发起拉取。

## 与刷新按钮的关系

传输方式栏右侧的 **刷新** 按钮会重新检测与各设备的连接（连接诊断）。检测过程中刷新图标会旋转；**圆点颜色会随检测结果更新**，但圆点本身不表示「检测中」——检测期间通常仍显示上一次的结果。

## 常见问题

**为什么 WebRTC 是主题色而不是绿色？**  
表示尚未对该路线做 WebRTC 专项检测。若 HTTP 已可用，系统可能跳过 WebRTC 探针以节省时间。你仍可切换到 WebRTC 手动尝试。

**为什么 HTTP 是琥珀色但仍可点击？**  
琥珀色表示直连尚未验证，但此路线允许 **尝试切换**。切换后发送时，客户端会再次尝试建立连接。

**设备列表头像上的圆点和这里一样吗？**  
不一样。设备列表上的圆点表示 **整台设备** 的综合在线状态（在线 / 检测中 / 离线；App 端还有「可拉取」的蓝色状态）。传输方式栏的圆点是 **每条路线各自** 的状态。

## 相关功能

- **连接诊断**：点击刷新或进入诊断流程，可逐步查看 HTTP 直连、信令、反向拉取、WebRTC、S3 等检测结果。
- **手动切换传输方式**：点击某条路线即可切换；与自动选择模式配合使用。
